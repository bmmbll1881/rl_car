# 项目记忆

## 交接背景

- 当前项目刚完成交接。
- 当前超车行为较难实现。交接描述认为，问题可能与智能体仅使用激光雷达传感器有关。
- 初步方向是评估并增加适用的传感器，以改善超车所需的环境感知。传感器选型和实现方式尚未确定，应先结合现有环境、观测空间和训练流程评估。

## 研发协作角色

- AI 研发总指挥负责任务拆解、方案定调、质量验收和资源调度。
- 深度方案评审、日常规划和标准代码审查由总指挥负责。
- 明确的功能实现，以及批量修改、补测试、数据清洗和命令执行等工作，优先委派给 WorkBuddy（DeepSeek-V4.1-Flash）。遇到可自行解决的问题时，受托 Agent 应继续推进，减少不必要的中断询问。
- 总指挥不承担机械性编码或重复性劳动。每次委派一个边界清楚的任务，并在委托中写明目标、输出格式、工具指导、任务边界和 Done 条件。
- 对委派结果进行独立验收，包括检查工作区变更、阅读 diff，并按任务需要运行测试。验收不通过时，要求受托 Agent 返工。
- 不需要用户输入时持续推进后续工作。只有遇到无法解释的失败或涉及删除数据、强推、修改仓库外内容等高风险操作时，才暂停并询问用户。
- 避免同时派发多个 WorkBuddy 任务。

## 当前待推进方向

先检查现有传感器观测、环境状态与超车逻辑，明确激光雷达观测对超车决策的限制，再评估可行的传感器补充方案及其对观测空间、训练和评测的影响。此条目记录的是初步方向，不代表已确定具体传感器或实施方案。

## 超车训练闭环（2026-11-20 完成本轮）

- 显式配置：`configs/rarl_overtake.json`，开启 `hazard_mode=ttc`、`ttc_features`、`action_risk`、`safety_shield`、`lane_aware`、`lane_clearance_features`、`overtake_lock`；策略输入 72 维。
- 奖励语义已改：`lane_change_bonus=1.0` 只在**计划中的安全变道真正完成**时支付一次（旧实现按"选了轻转向"逐步付费，在 `overtake_lock` 下永远不触发）。机会判定 = 本车道前车 <18 m、相邻车道侧向净空 ≥7 m、前向间隙比本车道多 ≥5 m。
- 安全屏蔽现在可以否决战术锁：锁定的硬转向若触发 TTC/动作风险屏蔽，则放弃变道并刹车（此前锁分支直接 `return`，屏蔽被绕过）。
- 超车指标：`OvertakeTracker` 统一给 `episodes.csv` / `evals.csv` / `evaluate.py` / `diagnose_risk.py` 提供机会步数、朝目标变道比例、保持/刹车比例、变道数、朝计划方向完成数、奖励次数；`diagnose_risk.py` 的 `--config` 已改为可选（默认读 run 目录里的配置），不再重复调用 `_action_mask()`（旧写法会二次推进冷却）。
- 修复了评估入口：`evaluate.py` 与多个脚本导入的 `reset_agent` / `advance_agent` 原本不存在（`evaluate.py` 直接 ImportError）；`evaluate_agent` 现在会调用 `reset_episode` / `observe_transition`，对应测试通过。
- 性能：把 `TTCCollisionRisk` 的净空边界提到 rollout 外层（每个交通模式只算一次），每步从 ~58 ms 降到 ~26 ms，`action_risk` 仍是主要成本（46 步/s）。

- 4 096 步：36.8 s（111 步/s），验证/测试评估全部跑通；成功率 0。
- 20 000 步：116 episodes，161.4 s（124 步/s）；4 个 episode 共 63 个机会步，5 次计划变道完成并触发奖励。

## 超车奖励漏洞修复与 2026-11-20 对照实验

定位到的四个漏洞（都已在 `autodrive/algos/rarl.py` 中修复或记录）：

1. `lane_change_bonus` 可被"左右摆动"刷分：判定只要求"跨进计划车道"，策略可 1→2→1→2 每跨一次收一次。
   现要求四点同时成立：方向与规划一致、锁的目标车道、距上次奖励已前进 ≥`lane_change_min_progress`(12 m)、
   完成后目标车道侧向 ≥7 m 且前向 ≥`lane_change_min_front_gap`(8 m)。160k 评估里 90 次变道只有 6 次通过校验。
2. 变道完成后没有任何后续追踪：`_overtake_target` 一到车道就清空，只有冷却，没有"是否真的超过前车"。
   现引入 pass window（`overtake_window_steps` / `overtake_pass_margin`）与"阻挡车辆被甩到身后"的 `overtake_passes` 指标。
3. TTC 屏蔽实际上永远不会触发：`TTCCollisionRisk.estimate` 把危险度乘上模式信念权重（7 模式≈1/7），
   单车 `ttc_front_hazard` 上限≈0.14 < `shield_hazard_threshold`=0.5，`action_risk` 同样封顶 <0.25。
   `diagnose_risk` 的 `front_hazard_steps` 恒为 0 即为证据。按要求保留风险栈不动，改为在奖励里用
   `safe_progress_min_gap`(12 m) 这一几何闸门，防止"贴着前车冲刺"拿奖励。
4. 课程环境没有"变道后安全加速"目标：环境奖励是 `+0.02·ds −0.1/步`，TTC 惩罚最多 −1.0/步，
   站住不动是局部最优（30k 旧模型 94% 的步选择刹车、0.14 m/s）。新增 `safe_progress_weight`：
   只对**沿轨道真实前进量**付费，且受 TTC 危险、动作风险、本车道前车间距三重校验，超过
   `safe_speed_target` 的部分不计奖；窗口内乘 `overtake_progress_multiplier`。

新增配置：`configs/rarl_overtake_legacy.json`（旧奖励基线）、`rarl_overtake_hardened.json`（只加校验）、
`rarl_overtake.json`（+前进奖励 0.2）、`rarl_overtake_prog06.json`（前进奖励 0.6）。
